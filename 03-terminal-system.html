终端系统

1. 概述

终端系统由 PTY 管理、Shell 集成、块模型解析、命令通知和外部 CLI 检测
五个子系统组成。

2. PTY 管理

2.1 当前实现

  • 使用 node-pty（N-API + 预编译二进制）。
  • 多终端标签、重命名、关闭确认、进程树。

2.2 Rust 替代

  • 使用 portable-pty crate。
  • 需要自行处理 IPC 通信。

3. Shell 集成

3.1 注入机制

packages/terminal-service 拥有集成脚本的字符串常量和纯函数
shellIntegrationSpawn()，映射 (shell, dir, enabled) → {args, env}。

  • zsh — ZDOTDIR shim，记录并恢复用户 ZDOTDIR，
    .zshrc 注册 precmd/preexec hooks 发射 OSC 133 序列。
  • bash — --init-file shim，安装 PROMPT_COMMAND + DEBUG trap。
  • fish — XDG_DATA_DIRS prepend，使用 fish 事件处理器。

3.2 降级

  • 其他 shell 或 settings.terminal.shellIntegration = false 时，
    终端降级为纯 scrollback，功能消失，无错误。

4. 块模型

4.1 块类型

  • command — 一个 shell 命令：prompt → command line → output → exit code。
  • turn — 外部 Agent 会话边界。

4.2 解析位置

解析在 Renderer 进行，通过 xterm 的 registerOscHandler。
块位置是 xterm markers，自然存活于滚动。

4.3 命令文本读取

从 buffer 的 B marker（记录 cursor column）到 C 时的 cursor 位置。
无私有转义序列携带命令文本，兼容任何已有 OSC 133 集成。

5. 进度报告

优先级：

  1. OSC 9;4（ConEmu 方言）
  2. 已知格式解析（保守 12/96 式计数器）
  3. 不确定（"running · elapsed"，不显示百分比）

同一数字供给三个表面：终端行进度环、状态栏进度项、macOS Dock 图标。

6. 命令通知

  • 命令完成时发送通知。
  • 未聚焦终端 dim 处理。

7. 外部 CLI 检测

7.1 检测机制

TerminalManager 轮询 pty.process（PTY 前台进程标题）~700ms。
匹配已知 Agent CLI 列表进入 agent 状态。

7.2 已知 CLI

  • claude — Claude Code
  • codex — Codex CLI
  • 可通过环境变量覆盖（测试用）

7.3 会话开始

  1. 创建 external session task。
  2. 捕获 entry snapshot（git write-tree 临时索引）。
  3. 非 git 项目降级：无 snapshot，first-seed content 成为 baseline。

7.4 会话记账

  • watcher 过滤（.git/, ignore globs, 产品 artifacts）。
  • 每个 touched path 从 snapshot tree blob 建立 ChangeService baseline。
  • 变化记录 author: 'agent', toolCallId: null。

7.5 会话结束

  • 任务转 REVIEW_READY。
  • Pane 返回 dock。
  • 打印摘要行。

8. 终端编排

8.1 六个原语

工具说明
terminal.list列出可见兄弟终端
terminal.create创建 shell/Claude/Codex worker
terminal.send注入文本 + 可选 Enter
terminal.wait等待命令退出/安静/正则
terminal.read读取 ANSI-free 内存 tail
terminal.kill兼容性端点（agent 调用禁止）

8.2 wait 三种模式

  • command — OSC 133 D;exit，返回真实 exit code。
  • quiet — 驻留 TUI，settle window。
  • until — 正则匹配，仅评估 wait 开始后的输出。

8.3 外部控制门

Unix domain socket（<userData>/ctl.sock，mode 0600）上的 HTTP，
token 必需。路由镜像六个工具。

失败语义：

  • 403 bad/missing token
  • 404 unknown target
  • 409 depth/self-control refusal
  • 429 over budget
  • 501 orchestration disabled

9. Codex/Claude 的 MCP 能力注入

9.1 环境变量注入

每个产品 spawn 的 PTY 终端接收三个环境变量：

text
CHARTER_TERM_ID       → 终端唯一 ID
CHARTER_CTL           → Unix Socket 路径 (如 /tmp/charter-xxx/ctl.sock)
CHARTER_CTL_TOKEN     → 随机鉴权 token (每次启动重新生成)

9.2 Codex 发现 MCP 门

Codex CLI 运行在 Charter 终端内时：

  1. 读取 CHARTER_CTL 环境变量
  2. 连接 Unix Socket，发送 HTTP 请求（带 Bearer token）
  3. 获得 terminal_list/create/send/wait/read/kill 六个工具
  4. Codex 可以创建自己的 worker 会话（变成 orchestrator）

9.3 编排工作循环

text
1. terminal.list    → 查看现有 worker，避免重复创建
2. terminal.create  → 创建 shell/Codex/Claude worker
3. terminal.send    → 发送指令（bracketed paste）
4. terminal.wait    → 等待完成（OSC 133 / quiet / regex）
5. terminal.read    → 读取输出（ANSI-stripped, in-memory tail）

9.4 安全约束

  • 深度限制 2 层（worker 不能再创建 worker）
  • 调用者不能 send/kill 自己的终端
  • 用户键盘输入 = takeover，队列自动保持
  • terminal.kill 对 agent 调用禁止（R4）

10. 终端文件链接

⌘+单击 file token：

  • html/svg/pdf → 系统浏览器打开。
  • 其他文件 → 编辑器打开到 :line。

识别方式：OSC 8 + 正则双轨。
