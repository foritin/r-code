架构总览

1. 系统定位

一款本地优先、任务原生、可观察、可审查、可回滚的桌面 Agentic IDE。
支持传统 IDE 操作（编辑、搜索、终端、 Git）与 Agent 工程链路
（任务定义、权限审批、代码修改、验证、审查、回滚）。

2. 进程拓扑

2.1 进程划分

2.2 设计原则

  • Main 进程承载所有宿主服务：窗口、Secret Store、SQLite、Task Engine、
    Tool Gateway、Permission Engine、ChangeService、Workspace/Document/Git/ Search/Verification/Terminal 服务。
  • Agent Worker 仅承载模型回路：工具调用经 IPC 回到 Main 的 Tool Gateway
    执行，Worker 进程内没有任何文件/命令执行器，也没有密钥存储。
  • 事件流：Worker → Main（持久化 + 投影）→ Renderer。

2.3 安全含义

  • 模型回路（最接近不可信输入的代码）运行在能力最小的进程里。
  • 工具执行点与权限检查点合一。
  • Main 承担更多工作，所有 I/O 保持异步，哈希/大 blob 处理走流式。

3. 多项目挂载

3.1 ProjectContext

每个项目对应一个 ProjectContext，包含：

  • DocumentStore facade
  • ChangeService
  • BlobStore
  • ToolGateway
  • PermissionEngine
  • VerificationService

以 mount root（项目规范路径或任务 worktree 路径）为键，
惰性创建，独立于焦点编辑器 workspace 存活。

3.2 Worktree 隔离

同一项目的并行任务使用 git worktree 隔离：

text
git worktree add -b charter/<taskId> <userData>/worktrees/<wsId>/<taskId> HEAD

任务上下文挂载 worktree 根目录，工具、变更记录、审查、Live Board
全部在隔离树上操作。

4. 三层信息架构

text
Home (启动器 + 任务控制台)
  └─ Task Room (每任务页: 时间线、审批、变更、验证、决策)
       └─ Editor (按需的完整 IDE 功能)
  • Task Room 成为 Home 表面内的一级页面。
  • Editor 降级为按需工具，保留全部能力。
  • 提交任务不再自动切换到 workbench。

5. 会话模型

5.1 会话即对话

一个 Session = 一个连续对话，聊天与工作交织。
账按轮记（agent_runs.review_state），验收/回滚/Answered 结算到 IDLE 续聊。
ARCHIVED 是唯一关门。

5.2 任务状态机

text
IDLE → EXPLORING → IN_PROGRESS → REVIEW_READY → IDLE (accept/rollback)
                                  ↓
                               ARCHIVED (用户显式)
  • REVIEW_READY 是 Agent 完成不变量。
  • ACCEPTED/ROLLED_BACK 不再作为 resting task state。
  • 按轮回滚（最新已结轮逆序，字节级）。

6. 外部 CLI 集成

6.1 检测机制

TerminalManager 轮询 PTY 前台进程标题（~700ms），
匹配已知 Agent CLI 列表（claude、codex）进入 agent 状态。

6.2 会话生命周期

  1. 进入：创建 external session task，捕获 entry snapshot
    （git write-tree 临时索引）。
  2. 记账：watcher 过滤后，每个 touched path 从 snapshot tree blob
    建立 ChangeService baseline。
  3. 结束：任务转 REVIEW_READY，pane 返回 dock。

6.3 结构化 Replay 解析

增量最佳-effort 解析器，处理各 Provider 的 JSON 流：

  • 丢弃 thinking/reasoning 块。
  • 提取可观察动作（消息、计划、工具调用、结果）。
  • 不存储原始思维链。

7. Pi Agent 与外部 CLI 的关系

7.1 Pi Agent（第一方运行时）

  • 运行在 Charter 的 Agent Worker 进程内（独立子进程）
  • 所有工具调用必须经过 Tool Gateway + Permission Engine
  • Pi 的内置 read/bash/edit/write 被完全禁用，只注入 Charter 网关代理工具
  • 由 Charter 完全管理（创建、恢复、中断、归档）

7.2 Codex / Claude Code（第三方外部 CLI）

  • 运行在 Charter 的 PTY 终端内（和普通 shell 进程一样）
  • 完全绕过 Charter 的 Tool Gateway 和 Permission Engine
  • 被标记为 EXT（unmanaged/外部）
  • 用户手动启动/退出，Charter 只负责检测和记账

7.3 双向编排

text
Pi Agent ──(terminal.create)──→ PTY 终端内运行 Codex
                                    │
Pi Agent ──(terminal.send)────→ Codex 输入行
Codex ────(terminal.wait)────→ 执行完成
Pi Agent ──(terminal.read)────← Codex 输出

Codex ────(MCP 门)────────────→ 创建 shell worker

8. 会话回放 (Replay)

7.1 三层深度

  • Recap：回答"发生了什么？重要吗？"
  • Explore：回答"这一刻发生了什么？"
  • Verify：回答"什么证明了这个声明？我能批准吗？"

7.2 设计原则

  • 三个深度共享同一份事件与证据记录。
  • playhead、过滤器、证据选择、源边界在深度切换时保持稳定。
  • 永远不展示或重建隐藏 chain-of-thought。
  • 不能确认时必须明确说"记录无法确认"。

7.3 证据级别

级别说明
Verified已验证
Recorded结构化记录
Observed观察（普通 TUI）
Inferred推断
Missing缺失
