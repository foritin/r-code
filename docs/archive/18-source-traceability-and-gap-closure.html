3. 不应在重构中被省略的现有能力

审计时最容易遗漏的是“不是主聊天窗口”的能力。以下能力没有单独界面也必须进入产品切片：

  • 终端 shell integration、命令块、文件链接、受管终端与裸终端的差异。
  • 外部 CLI 会话发现、JSONL replay、恢复、用户级 instructions / wrapper 链。
  • 多 worktree、任务基线、外部改动冲突与按 hunk 审查。
  • Preview、截图、可视上下文和 artifact / feedback 附件。
  • Skills 使用追踪、项目记忆、会话考古、任务历史与可导出证据。
  • 隐私设置、secret redaction、CSP/navigation、支持包与 startup diagnostics。
  • 键盘导航、缩放、可访问 diff、窄视口布局与设计 token。

它们分别已有章节；任何“先做核心、以后补 UI”的阶段计划也应为这些能力预留 DTO、事件和
数据库 migration，而不是让其依赖临时字符串解析。

4. 已知的重构选择与非目标

决策规范立场原因
桌面 shellTauri v2 + 系统 WebViewRust host 与 React UI 分层，缩小默认攻击面
UIReact / TypeScript 可迁移而非强制 Rust UI保留 Monaco、xterm 和既有工作台投资
Agent runtime独立 worker + 显式 RPC 边界Pi SDK / provider 适配不污染高权限主进程
数据SQLite 事件投影 + content-addressed evidence可恢复、可审查、可导出
真实实现新仓 / 新 workspace 渐进切换不在当前生产 Electron 产品上进行破坏性替换

本指南不承诺：无条件兼容所有第三方 CLI 私有存档格式、把任何 Agent 的原始思维链永久保存、
绕过 OS 签名策略、或把用户目录中的所有文件自动纳入 Agent 可访问范围。

5. 审计复查方法

每次产品新增功能或修改重大行为时执行一次轻量复查：

  1. 先写用户可观察的行为和失败态，再找到对应 Task / Tool / Event / Evidence DTO。
  2. 将实现归入一条现有章节；若无归属，先新增规范页而不是把逻辑塞进 charter-main。
  3. 记录安全边界、数据归属、迁移和 E2E 场景。
  4. 更新本页矩阵、产品验收编号和运行手册的 gate。
  5. 对照 15-testing-strategy 与 17-delivery-release-and-operations 追加证据。

因此本页不是一次性的“来源注释”，而是防止重构在长期演进中再次漏功能的维护入口。

本页为可离线浏览的重构规范；代码示例是实现合同，不是已交付源码。
