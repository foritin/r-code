安全模型

1. 概述

R-Code 的安全模型基于多层防御：进程隔离、权限引擎、路径边界、
凭据保护和日志脱敏。安全属于 P0，不得后置。

2. 进程隔离

2.1 Renderer 隔离

  • nodeIntegration=false
  • contextIsolation=true
  • sandbox=true
  • CSP 策略阻止内联脚本、外部框架、exfil-fetch

2.2 渲染层安全

  • 所有渲染层代码视为不可信。
  • IPC 消息必须 schema 校验。
  • 无直接 Node.js 访问。

3. 威胁模型

3.1 攻击面

攻击面威胁缓解
工具注入Agent 执行恶意命令Permission Engine + 审批
路径穿越读写工作区外文件canonical path + realpath 检查
提示注入恶意内容进入模型上下文默认不信任项目目录
凭据泄露API key 泄露Secret Store + safeStorage
终端注入恶意终端输出输出视为不可信文本

3.2 外部 CLI 风险

外部 CLI 运行在 Tool Gateway 和 Permission Engine 之外。
补偿措施：

  • 自动 entry snapshot。
  • byte-exact rollback。
  • 完整变更记账。
  • 正常 REVIEW_READY 门。

4. 路径边界

4.1 规范路径

  • 所有文件操作使用 canonical path。
  • 拒绝符号链接逃逸。
  • TOCTOU 防护。

4.2 工作区 containment

  • 工具只能访问工作区文件。
  • read_file 只能读工作区文件。
  • 路径穿越拒绝。

5. 凭据保护

5.1 Secret Store

  • 使用 OS keychain（macOS Keychain, Windows Credential Manager）。
  • API key 不落盘明文。
  • 内存中短暂存在。

5.2 不可检测性

  • Renderer heap snapshot 中不可检测。
  • localStorage 中不可检测。
  • 日志中不可检测。
  • support bundle 中不可检测。

6. 日志脱敏

6.1 脱敏规则

  • API key → ***
  • 令牌 → 前 4 位 + ***
  • 文件内容 → 截断或哈希

6.2 滚动缓冲

  • 终端输出缓冲 ~200 KB。
  • 仅内存，随终端消亡。

7. 依赖安全

7.1 依赖扫描

  • npm audit 定期检查。
  • 无 Critical/High 漏洞。
  • 第三方许可证合规。

7.2 边界检查

  • 仅 agent-runtime-pi 可 import Pi 包。
  • 边界 lint 强制。

8. 网络安全

8.1 外部导航

  • javascript:/file:/unknown-scheme 导航被拒绝。
  • window.open 被拒绝。

8.2 预览 iframe

  • iframe sandbox 授予固定权限。
  • picker 仅注入 plain-http loopback。
  • picker script posts-only + self-cleaning。

9. Electron Fuses

  • runAsNode off
  • NODE_OPTIONS/inspect off
  • asar integrity on
  • onlyLoadAppFromAsar on

10. Rust 安全优势

10.1 内存安全

  • 消除 use-after-free、buffer overflow。
  • 编译器保证。

10.2 类型安全

  • serde 反序列化即校验。
  • 所有权系统防止数据竞争。

10.3 并发安全

  • tokio 异步运行时。
  • 编译时防止数据竞争。

// 路径边界
struct PathGuard {
    root: PathBuf,
}

impl PathGuard {
    fn resolve(&self, path: &Path) -> Result<PathBuf, SecurityError> {
        let canonical = path.canonicalize()?;
        if !canonical.starts_with(&self.root) {
            return Err(SecurityError::PathEscape);
        }
        Ok(canonical)
    }
}

// Secret Store
struct SecretStore {
    keyring: keyring::Entry,
}

impl SecretStore {
    fn store(&self, key: &str, value: &str) -> Result<(), SecretError> {
        self.keyring.set_password(value)?;
        Ok(())
    }
    
    fn get(&self, key: &str) -> Result<Option<String>, SecretError> {
        match self.keyring.get_password() {
            Ok(pwd) => Ok(Some(pwd)),
            Err(keyring::Error::NoEntry) => Ok(None),
            Err(e) => Err(e.into()),
        }
    }
}

// 日志脱敏
fn redact_text(input: &str) -> String {
    // API key patterns
    let re = Regex::new(r"(sk-[a-zA-Z0-9]{48})").unwrap();
    re.replace_all(input, "sk-***").to_string()
}
