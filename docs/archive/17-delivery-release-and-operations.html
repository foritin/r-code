构建、发布、运维与恢复手册

1. 交付物边界

重构后的 R-Code 是一个签名/可验证的桌面产品，而不是只在开发机能运行的 Rust 二进制。每个
发布版本至少产出：

text
R-Code-<version>-<platform>.<installer>
SHA256SUMS
manifest.json                 # 版本、commit、构建时间、平台、依赖摘要
SBOM.spdx.json
release-notes.html

开发构建、候选构建、Beta 与 Stable 必须使用不同的更新通道和签名身份；不能把未签名开发包
描述成安全发布物。

2. 可重复构建链

阶段输入输出必须验证
依赖固定Cargo.lock、UI lockfile、公共合同 pin可解析的依赖图无未审查浮动依赖
静态检查Rust / TS 源码fmt、clippy、typecheck 结果零阻断错误
测试单元、集成、fixture、E2EJUnit / trace / 截图关键路径全绿
打包已构建二进制、WebView 资源、许可证各平台安装包安装、启动、卸载 smoke
签名与证明平台证书、notarization / Authenticode可验证包checksum 与签名匹配
发布版本说明、SBOM、更新 manifest渠道条目回滚版本仍可获取

建议 CI 只从干净 checkout 构建，并将 UI 构建产物、Rust 二进制、installer 与 manifest 的
commit SHA 交叉写入，防止“测试的是一个版本、发布的是另一个版本”。

3. 环境与密钥管理

  • 构建签名证书、更新签名私钥、发布 token 与测试模型 key 均由 CI secret store 注入。
  • 本地开发的 .env、config.toml、用户数据目录和截图支持包不进入版本控制。
  • 包内只包含公钥、更新 URL 与非秘密渠道信息；运行时凭据进入 OS keychain / 受限文件。
  • 生产日志使用结构化字段与 redaction：token、Authorization、Cookie、prompt 附件正文、
    完整终端输出默认不上传。

4. 发布门禁

4.1 每次合并请求

text
format → clippy/typecheck → unit → integration → security → build → targeted Electron/Tauri E2E

4.2 每个候选版本

  • 新装：干净用户数据目录能够完成启动、创建项目、创建任务、审批、审查与退出。
  • 升级：前一稳定数据目录迁移后可读；迁移失败保留原库和可导出的诊断。
  • 回滚：安装前一版本后，数据库版本不兼容时给出明确策略（只读、备份恢复或阻止启动）。
  • 安全：CSP / navigation、preload、路径边界、秘密扫描、依赖审计与权限默认值通过。
  • 视觉：真实桌面表面在目标和窄视口非空、无 framework overlay、关键路径截图留证。
  • 可访问性：键盘聚焦、语义 diff、缩放和屏幕阅读器关键提示通过。

5. 运行时可观测性

运行时日志按以下关联 ID 串联，但避免记录隐私正文：

text
app_instance_id → workspace_id → task_id → run_id → tool_call_id → terminal_id
信号用途最小字段
生命周期日志启动、迁移、退出、崩溃app 版本、平台、错误分类
任务事件解释状态机和证据task/run、旧新状态、序号
工具账本审计动作与权限风险、决定、参数摘要、结果摘要
终端事件诊断 PTY / CLIterminal、cwd hash、退出码、截断标志
性能测量发现回归操作名、耗时、对象规模

支持包必须由用户显式导出，先预览将包含的文件，再对敏感字段做 redaction。导出失败不可影响
正常任务数据。

6. 故障分流与恢复

症状首选动作禁止动作
数据库迁移失败保留原 DB、创建备份、进入诊断页自动删除 / 重建用户 DB
Worker 意外退出标记 Run 为中断，显示最后安全事件把它显示为“已完成”
PTY / 外部 CLI 断开保留历史缓冲与失联原因，允许重新附着猜测并执行上次命令
权限卡卡住校验待决记录、提供取消/恢复创建第二份决定记录
文件基线冲突比较当前磁盘、基线和任务改动静默覆盖外部变更
更新后启动失败提供上一版本、日志位置和恢复向导建议用户全局关闭 OS 安全保护

恢复策略的核心是“保留证据，缩小动作”。任何自动修复都必须可解释、可逆，且不扩大可访问的
文件或权限范围。

7. 版本兼容性和数据保留

  1. 数据库 migration 必须单向编号、事务化、可在 staging copy 上预检。
  2. 事件 payload 和 IPC 协议采用版本化 DTO；未知字段可保留/忽略，未知危险动作默认拒绝。
  3. 大型 artifacts、截图、终端缓冲和 preview 证据设容量和保留期，但引用删除前先更新索引。
  4. 用户可以导出 task、审计、diff 和验证结果；删除项目或遗忘记忆必须有范围和确认。
  5. 任何 telemetry 默认 local-only；联网诊断或更新检查均应可关闭并被清楚标示。

8. 上线签核

  • 版本、commit、公共合同 pin 和 SBOM 已对齐。
  • 安装/升级/回滚/卸载 smoke 已在每个目标平台执行。
  • 数据迁移、worker 中断、权限待决、外部 CLI 断开、回滚冲突均有演练记录。
  • 关键 E2E、security、性能和视觉证据可追溯到候选包。
  • 证书/发布 secret 未出现在日志、产物或支持包。
  • Beta 的未签名/未公证状态（若存在）在下载页和应用内明确披露。

这是一份重构目标的发布规范；具体 Rust crate 与 UI 实现见前序章节，当前 Electron 工程的
脚本名称不是此规范的外部依赖。

本页为可离线浏览的重构规范；代码示例是实现合同，不是已交付源码。
