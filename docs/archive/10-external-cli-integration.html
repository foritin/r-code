外部 CLI 集成

1. 概述

Charter 支持外部 CLI（Claude Code、Codex）作为一等公民运行。
外部 CLI 会话可被检测、记账、审查，并与内部任务无缝集成。

2. 检测机制

2.1 前台进程轮询

  • TerminalManager 轮询 pty.process（PTY 前台进程标题）。
  • 轮询间隔 ~700ms。
  • 匹配已知 Agent CLI 列表进入 agent 状态。

2.2 已知 CLI

CLI进程名存储路径
Claude Codeclaude~/.claude/projects/<munged-cwd>/<uuid>.jsonl
Codex CLIcodex~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<uuid>.jsonl

2.3 信号选择

  • 使用 PTY 前台进程标题作为信号。
  • 不使用 OSC 标题（不稳定）。
  • 不使用 alternate-screen 切换（Claude Code renderer 模式不稳定）。

3. 会话生命周期

3.1 进入 Agent 状态

  1. 创建 external session task。
  2. 捕获 entry snapshot：
  • Git 项目：git write-tree 临时索引（GIT_INDEX_FILE + add -A）。
  • 非 Git 项目：无 snapshot，first-seed content 成为 baseline。
  1. 任务状态 READY → EXPLORING → IN_PROGRESS。

3.2 记账

  • Workspace watcher 过滤（.git/, ignore globs, 产品 artifacts）。
  • 每个 touched path 从 snapshot tree blob 建立 ChangeService baseline。
  • 变化记录 author: 'agent', toolCallId: null。

3.3 结束 Agent 状态

  • 任务转 REVIEW_READY。
  • Pane 返回 dock。
  • 打印摘要行。
  • 零变化会话遵循 "Answered" 仪式。

4. 会话恢复

4.1 定位对话 ID

  • 基于时间窗口匹配 transcript mtime。
  • 找到精确 session ID。

4.2 恢复命令

  • claude --resume <id>
  • codex resume <id>

5. 结构化 Replay 解析

5.1 解析器

增量最佳-effort 解析器，处理各 Provider 的 JSON 流。

5.2 设计原则

  • 丢弃 thinking/reasoning 块。
  • 提取可观察动作。
  • 不存储原始思维链。

5.3 Codex 事件映射

Codex 事件解析结果
thread.started标记"structured capture connected"
turn.started标记 turn 开始
turn.completed报告完成（含 usage）
item.started/completed (command_execution)记录命令执行 + exit code
item.started/completed (agent_message)提取消息文本
reasoning丢弃

5.4 Claude 事件映射

Claude 事件解析结果
system (init)标记"structured capture connected"
assistant/user (text)提取消息文本
assistant/user (tool_use)记录工具调用
assistant/user (tool_result)记录工具结果
result报告完成/失败
thinking/redacted_thinking丢弃

6. 外部控制门

6.1 通信

  • Unix domain socket：<userData>/ctl.sock（mode 0600）。
  • HTTP 协议，token 必需。

6.2 路由

方法路径说明
GET/v1/terminals列出终端
POST/v1/terminals创建终端
POST/v1/terminals/{id}/send注入文本
POST/v1/terminals/{id}/wait等待完成
GET/v1/terminals/{id}/read读取输出
DELETE/v1/terminals/{id}/kill关闭终端

6.3 失败语义

状态码含义
403bad/missing token
404unknown target
409depth/self-control refusal
429over budget
501orchestration disabled

7. 指令面投影

7.1 Skill 安装

  • ~/.claude/skills/charter-terminal/SKILL.md
  • ~/.codex/skills/charter-terminal/SKILL.md
  • 原子写入（tmp + rename）。
  • 仅用户点击时写入。

7.2 AGENTS.md Snippet

7.3 触发条件

  • 并行实验。
  • 可用性门（CHARTER_CTL 存在）。

8. 用户级指令面

8.1 安装机制

设置一键安装到：

  • 托管 Skills 库
  • ~/.claude/skills/
  • ~/.codex/skills/

8.2 新鲜度检查

  • IPC skills.charterTerminalStatus 逐字节比较。
  • 报告 installed/upToDate/error。

8.3 Wrapper 链加固

  • CLI 解析追加 ~/.local/bin 等安装目录。
  • CLI 消失即清理 stale wrapper。

9. 双向编排

9.1 Pi Agent → Codex（主要路径）

Pi Agent 作为 orchestrator，创建 Codex worker：

  • 通过 terminal.create(launch: 'codex') 创建 PTY 终端
  • 通过 terminal.send/wait/read 与 Codex 交互
  • Codex 保留自己的权限模型，不受 Charter Permission Engine 控制
  • 需要用户审批（R2 风险）

9.2 Codex → shell worker（反向路径）

Codex 手动启动后，通过 charter MCP server 变成 orchestrator：

  • Codex 通过环境变量发现 MCP 门
  • 获得 terminal.* 六个工具
  • 可以创建 shell/Claude worker
  • 深度限制仍然适用（2 层）

9.3 编排约束

约束说明
深度限制最多 2 层（orchestrator → worker）
预算每 orchestrator ≤5 活 worker，≤30 sends/min
自我控制不能 send/kill 自己的终端
Worker 隔离Worker 不能再创建 worker
用户接管键盘输入 = takeover，队列自动保持

10. 终端文件链接

9.1 交互

  • ⌘+单击 file token。
  • html/svg/pdf → 系统浏览器打开。
  • 其他文件 → 编辑器打开到 :line。

9.2 识别

  • OSC 8 + 正则双轨。

10. 安全考虑

10.1 输出视为不可信

  • 终端输出是 untrusted text。
  • 不遵循输出中的指令。

10.2 PTY 写入面收窄

  • 结构化引用 + 永不回车。
  • 注入内容由 schema 限定。

10.3 台账

  • 注入即记 external.contextInjected 台账事件。
  • 不含选区全文，只含路径/区间/哈希。

// 外部 CLI 检测
struct CliDetector {
    known_clis: Vec<String>,
    poll_interval: Duration,
}

impl CliDetector {
    async fn poll(&self, pty: &PtyHandle) -> Option<CliSession> {
        let process = pty.foreground_process();
        if self.known_clis.iter().any(|cli| process.contains(cli)) {
            Some(CliSession::new(process))
        } else {
            None
        }
    }
}
