Agent 运行时

1. 概述

Agent 运行时是模型回路的承载者，运行在独立 Worker 进程内。
它通过 IPC 与 Main 进程通信，所有工具调用回到 Main 的 Tool Gateway 执行。

2. 运行时类型

2.1 Pi Adapter

  • 使用 Pi SDK（当前为 JS/ESM+wasm 专用）。
  • 通过 createAgentSession({ noTools: 'all', customTools: [...] }) 完全禁用 Pi 内置工具。
  • 只注入产品 Tool Gateway 代理工具。
  • AuthStorage 使用内存后端，由产品 Secret Store 注入凭据。
  • SessionManager 指向 AppData/runtime 下的产品管理目录。

2.2 Mock Runtime

  • 确定性后端，用于测试/dev。
  • 支持 scenario engine 驱动事件脚本。

3. 进程生命周期

3.1 启动

  1. Main 进程 fork Worker 进程。
  2. Worker 初始化 Agent Runtime。
  3. 建立 IPC 通道（MessagePort / Unix Socket）。
  4. Worker 发送 ready 握手。

3.2 运行

  1. 用户提交任务 → Main → Worker。
  2. Worker 调用模型，产生事件流。
  3. 工具调用经 IPC 回到 Main 的 Tool Gateway。
  4. 结果经 IPC 返回 Worker。

3.3 崩溃恢复

  • Worker SIGKILL → Main 标记任务 INTERRUPTED。
  • Main 驱动恢复页。
  • Worker 重启后扫描 orphaned runs。

5. Agent 作为 Orchestrator

5.1 编排能力

Pi Agent 可以通过 Tool Gateway 的 terminal.* 工具创建并指挥外部 worker 会话：

text
Pi Agent (Agent Worker 进程)
    │
    │  terminal.create(launch: 'codex')  ← R2 风险，需用户审批
    ▼
┌─────────────────────────────────────────┐
│  PTY 终端内运行 Codex CLI               │
│  - Codex 保留自己的权限模型             │
│  - 不受 R-Code Permission Engine 控制  │
│  - 标记为 EXT (unmanaged)              │
└─────────────────────────────────────────┘
    │
    │  terminal.send(id, "指令")  ← Pi Agent 向 Codex 输入行打字
    │  terminal.wait(id)          ← Pi Agent 等待 Codex 完成
    │  terminal.read(id)          ← Pi Agent 读取 Codex 输出
    ▼
Codex 执行结果返回给 Pi Agent

5.2 关键限制

维度说明
调用方式不是直接 API 调用，是 PTY 终端交互
权限控制Codex 保留自己的权限模型，不受 R-Code Permission Engine 控制
审批要求terminal.create 是 R2，需要用户审批
深度限制编排深度 2 层，worker 不能再创建 worker
安全补偿entry snapshot + byte-exact rollback + 完整记账

5.3 编排工作循环

text
1. terminal.list    → 查看现有 worker
2. terminal.create  → 创建 Codex/Claude/shell worker
3. terminal.send    → 向 worker 发送指令
4. terminal.wait    → 等待 worker 完成
5. terminal.read    → 读取 worker 输出

5.4 反向编排

如果用户在 R-Code 终端里手动启动 Codex，Codex 可以通过 r-code MCP server 使用 terminal.* 工具，Codex 变成 orchestrator，可以创建 shell/Claude worker。

6. 事件模型

5.1 AgentEvent

typescript
interface AgentEvent {
  type: 'message' | 'tool_call' | 'tool_result' | 'plan' | 'state';
  taskId: string;
  runId: string;
  data: unknown;
  timestamp: number;
}

5.2 事件流

text
Worker → Main (持久化 + 投影) → Renderer

5.3 事件类型

  • message — 模型文本输出（仅 text deltas，不含 thinking）。
  • tool_call — 工具调用请求。
  • tool_result — 工具调用结果。
  • plan — 计划更新。
  • state — 状态变更。

6. 任务状态机

6.1 状态

text
IDLE → EXPLORING → IN_PROGRESS → REVIEW_READY → IDLE
                                  ↓
                               ARCHIVED

6.2 轮次结算

  • 每轮有 review_state：pending | accepted | auto_accepted | rolled_back | answered。
  • 零变化轮次自动结算为 answered。
  • 验收/回滚结算到 IDLE，不关房间。

6.3 Full 模式

  • 验证通过轮次自动结算（auto_accepted）。
  • 验证失败轮次停在 REVIEW_READY。

10. Pi SDK 集成方案

由于 Pi SDK 是 JS/ESM+wasm 专用，存在三条可选路径：

路径 A：嵌入 JS 引擎

  • 使用 deno_core 或 rquickjs 嵌入微型 JS 运行时。
  • 直接加载 Pi SDK 的 ESM+wasm 包。
  • 复杂度高，两个运行时共存。

路径 B：自行封装

  • 重写 LLM 调用 + 工具定义 + 流式输出。
  • 工作量大，需完全重写 agent-runtime-pi。

路径 C：MCP 解耦

  • Agent 作为独立二进制，通过 MCP 与宿主通信。
  • 任何语言的 Agent 实现都能接入。
  • 最优雅，但依赖生态支持。
