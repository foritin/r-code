会话编排

1. 概述

会话编排允许一个 Agent 会话（orchestrator）打开并指挥兄弟 worker 会话。
六个原语能力：list, read, send, create, wait, kill。

2. 核心设计

2.1 一个心脏，两扇门

  • 托管 runtime 和外部 CLI 走同一个 Tool Gateway。
  • 同一个 Permission Engine，同一个 Ledger。
  • 无第二条执行路径。

2.2 风险分级

工具风险说明
terminal.listR0列出终端
terminal.waitR0等待完成
terminal.readR1读取输出
terminal.createR2创建终端
terminal.killR3关闭终端
terminal.send动态注入文本

2.3 动态风险

send 根据目标前台进程动态定级：

  • 裸 shell → R2（命令执行）
  • TUI/Agent → R1（内容注入）
  • 控制字符 → R2

3. 深度限制

  • 编排深度限制 2 层（orchestrator → worker）。
  • Worker 不能再创建 worker。
  • 调用者不能 send/kill 自己的终端。
  • 主机端强制。

4. 预算与暂停

  • 每 orchestrator：≤5 活 worker，≤30 sends/min。
  • 两档暂停：per-worker "pause remote control"，fleet-wide "pause all"。
  • 暂停只排队新注入，不中断运行中命令。
  • 用户键盘输入 = takeover，队列自动保持。

5. 身份系统

5.1 Per-Terminal Token

每个产品 spawn 的 pty 接收三个环境变量：

  • CHARTER_TERM_ID — 终端 ID
  • CHARTER_CTL — 门地址
  • CHARTER_CTL_TOKEN — 随机 token

5.2 Token 特性

  • 内存存储（token → terminal 映射）。
  • 每次 app 启动重新生成。
  • 不落盘。
  • CHARTER_CTL_TOKEN_OVERRIDE 仅用于 dev/test。

6. 外部控制门

6.1 通信

  • Unix domain socket：<userData>/ctl.sock（mode 0600）。
  • HTTP 协议，token 必需。
  • 路由镜像六个工具。

6.2 失败语义

状态码含义
403bad/missing token
404unknown target
409depth/self-control refusal
429over budget
501orchestration disabled

6.3 门是翻译器

验证 token → 解析调用者终端 → 构建 ToolCallRequest → executeCall。

7. 指令面投影

7.1 三种投影

  1. 托管 Skills 库 — charter-terminal skill，设置一键安装。
  2. AGENTS.md snippet — 手动复制粘贴到项目 AGENTS.md。
  3. 托管 runtime — 不需要（工具描述原生）。

7.2 Skill 安装位置

  • ~/.claude/skills/charter-terminal/SKILL.md
  • ~/.codex/skills/charter-terminal/SKarter-terminal/SKILL.md
  • 原子写入（tmp + rename）。
  • 仅用户点击时写入。

7.3 触发条件

Skill 描述命名触发场景：

  • 打开/指挥另一个 terminal/Claude/Codex 窗口
  • 并行实验
  • 可用性门（CHARTER_CTL 存在）

8. Pi Agent → Codex 编排实例

8.1 端到端流程

text
Pi Agent (Agent Worker 进程)
    │
    │  1. terminal.list()
    │     查看现有 worker，避免重复创建
    │
    │  2. terminal.create({ launch: 'codex', initialText: '请审查这个计划...' })
    │     ↓
    │     Tool Gateway 检查风险级别 (R2)
    │     ↓
    │     用户收到审批请求 (rail badge / fleet tile / notification)
    │     ↓
    │     用户点击 "Allow once"
    │     ↓
    │     创建 PTY 终端，spawn codex CLI
    │     Codex 接收到 MCP 环境变量:
    │       - CHARTER_TERM_ID
    │       - CHARTER_CTL (socket path)
    │       - CHARTER_CTL_TOKEN
    │     ↓
    │     Codex 通过 charter MCP server 获得 terminal.* 能力
    │     (Codex 也可以变成 orchestrator)
    │
    │  3. terminal.send({ id, text: '继续执行' })
    │     ↓
    │     通过 bracketed paste 注入到 Codex 输入行
    │     Codex 保留自己的权限模型，独立审批
    │
    │  4. terminal.wait({ id, mode: 'command' })
    │     ↓
    │     等待 OSC 133 D;exit 信号，获取真实 exit code
    │
    │  5. terminal.read({ id, maxBytes: 32768 })
    │     ↓
    │     读取 Codex 输出 (ANSI-stripped, in-memory)
    │
    │  6. 结果返回给 Pi Agent，用于下一步决策

8.2 Codex 的双重角色

角色说明
作为 WorkerPi Agent 创建 Codex，Codex 执行特定任务后返回结果
作为 Orchestrator用户手动启动 Codex，Codex 通过 MCP 门创建 shell worker

8.3 Codex 的 MCP 能力注入

Codex CLI 运行在 Charter 终端内时，通过环境变量发现 charter MCP server：

text
CHARTER_TERM_ID      → 终端 ID
CHARTER_CTL          → Unix Socket 路径
CHARTER_CTL_TOKEN    → 鉴权 token

Codex 获得 terminal_list/create/send/wait/read/kill 六个工具，
可以创建自己的 worker 会话（但深度限制仍然适用）。

9. 审批模型

8.1 单记录多入口

一个 risky call 创建一个 permission_request，
UI 在多个入口渲染：

  • rail badge
  • fleet tile
  • worker-room card
  • mission-control "Needs you"
  • native notification

所有入口绑定同一记录，任何入口解决即清除全部。

8.2 长期规则

"Always allow for this task" 实现为 StandingRule，
作用域：(task, tool, target terminal)。

9. 用户级指令面

9.1 安装机制

设置一键安装到：

  • 托管 Skills 库
  • ~/.claude/skills/
  • ~/.codex/skills/

9.2 新鲜度检查

  • IPC skills.charterTerminalStatus 逐字节比较。
  • 报告 installed/upToDate/error。
  • 用户编辑副本显示 "update available"。

9.3 Wrapper 链加固

  • CLI 解析追加 ~/.local/bin 等安装目录。
  • CLI 消失即清理 stale wrapper。

10. 结构化 Replay 解析

10.1 解析器

增量最佳-effort 解析器，处理各 Provider 的 JSON 流。

10.2 Codex 事件映射

Codex 事件解析结果
thread.started标记"structured capture connected"
turn.started标记 turn 开始
turn.completed报告完成（含 usage）
item.started/completed (command_execution)记录命令执行 + exit code
item.started/completed (agent_message)提取消息文本
reasoning丢弃

10.3 设计原则

  • 丢弃 thinking/reasoning 块。
  • 提取可观察动作。
  • 不存储原始思维链。
