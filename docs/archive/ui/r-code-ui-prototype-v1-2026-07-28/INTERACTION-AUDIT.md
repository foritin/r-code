# R-Code UI / Interaction Audit

审计日期：2026-07-27
类型：桌面 App UI
范围：12 张核心原型、4 张任务运行交互状态、统一应用壳层与交互 Demo

## 结论

视觉方向已经成立：工作台连续、层级安静、橘色只承担选择与操作，卡片嵌套疲劳已基本消失。继续加容器不会让页面更清楚，下一阶段的提升点主要在“路径是否真实、状态是否可恢复、动作是否给反馈”。

首轮评审：`8.2 / 10`；交互补齐后：`9.0 / 10`。AI 模板感评级为 `A`：没有紫色科技渐变、Bento 拼盘、装饰性图标阵列、统一大圆角卡片或虚构指标墙。

## 保留（Keep）

- 项目仪表盘采用连续平面、统计条、数据行和收起检查器，避免了“框中框”。
- 全局壳层稳定，11 个产品页的品牌区、搜索区、新对话与状态栏一致。
- 一组动作只有一个橘色主按钮；危险、成功、等待均有文字或图标，不依赖颜色单独编码。
- 任务工作台把主内容、对象列表和上下文检查器分开，信息密度高但扫描路径明确。
- 终端只有真实输出区使用深色，不拿深色和霓虹当装饰。

## 已落地的优化

### 高优先级

1. **项目参数化**：`r-code` 与 `api-server` 均可从项目树或项目菜单进入自己的仪表盘；URL 保留 `project`。
2. **对话 / 新对话分流**：左栏“对话”进入对话列表，橘色“新对话”进入创建入口；未附加项目时保持纯对话语义。
3. **任务 ID 与标签路由**：任务 URL 保留 `task`；补充任务概览、任务文件页。尚未发生的阶段明确不可用，并说明原因。
4. **授权范围明确**：“始终允许此工具”改为“始终允许此命令”，确认层写清项目、完整命令、风险与可撤销范围。
5. **审核摘要降权**：活动页只提供“查看完整审核”，接受、请求修改与回滚放到完整审核页，并对接受/回滚再次确认。

### 中优先级

6. **项目级入口集中**：项目选择器提供项目概览、项目文件、项目记忆与项目设置，不把稳定项目导航塞进检查器。
7. **搜索升级为命令面板**：支持 `Ctrl/⌘ K`、分组结果、即时过滤、方向键、Enter 与 Esc。
8. **检查器语义与状态完整**：新对话、对话列表和应用设置不显示右栏；“项目动态”只在项目作用域出现。审核摘要、权限详情等上下文收起后保留原标签，再展开恢复原内容与操作。
9. **关键动作反馈统一**：权限、保存、诊断、审核、分支、复制路径均有处理中、确认、成功或失败反馈。
10. **全局 / 项目设置分界**：模型服务与 CLI 作为应用设置；访问模式与项目记忆从项目菜单进入。

### 视觉与可访问性

11. **双主题**：浅色延续原母版；深色使用暖炭黑表面层级，不做简单反色。终端在深色主题里仍比应用画布更深一级。
12. **主题入口**：快速切换位于顶栏“帮助”和“设置”之间；完整选择仍归属“设置 → 外观”。
13. **图标策略**：功能图标继续使用 `currentColor`；品牌 App Icon 提供 dark / light 两个版本，不用 CSS 滤镜反色。
14. **交互可见性**：焦点、悬停、不可用、处理中、成功和危险确认均有独立状态，并遵守减少动态效果偏好。

### 任务运行与子代理

15. **默认降噪**：任务运行默认只有一行摘要和低幅度呼吸状态，不直接铺开命令、工具调用、生命周期事件或右侧面板。
16. **三级披露**：摘要点击后展开可读活动；活动点击后展开单条命令详情；子代理点击后才打开右侧检查器。
17. **公开信息边界**：子代理只展示状态、耗时、公开活动与结果，不显示私有推理；内部事件名与 JSON 只进入诊断日志，不进入普通对话界面。
18. **可恢复与可关闭**：活动和子代理列表可以独立收起；检查器关闭后恢复单栏主对话，不留下空白轨道。

## 仍属于 Demo 的边界

- 所有业务数据来自固定 fixtures，不连接真实后端，也不会真正执行命令或写入文件。
- “项目终端”以确认层模拟创建；“任务终端”仍使用既有任务分镜。
- 桌面工作台的设计最小宽度为 `1180px`；更窄窗口应在生产实现中切换为侧栏抽屉，而不是继续压缩三栏代码工作台。

## 验收重点

- 项目切换不会落到另一项目的数据。
- 任务标签不会把分页或编译任务错误带到队列任务的差异画面。
- 摘要页不能无确认地接受或回滚变更。
- 全局页不得因为收起上下文而回退成“项目动态”；审核摘要与权限详情必须可原样收起、恢复。
- 深色主题中代码差异、语义色、输入框与终端没有浅色孤岛。
- 所有看起来可点击的顶栏入口都有浮层、跳转或明确的不可用说明。
