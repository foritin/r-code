# R-Code UI Prototype V1 — Unified Baseline

状态：B+C 项目仪表盘母版与 01、02、04–12 页面集均已完成确定性重绘，`00-master-project-dashboard.png` 是唯一视觉基准。

本规范用于约束后续所有高保真原型。任何页面都必须复用同一套应用外壳、组件、术语和演示数据。页面差异只发生在主工作区，不得重新设计全局导航。

## 1. 设计目标

- 产品类型：本地优先的桌面开发代理工作台。
- 主要场景：跨项目掌握任务、进入项目仪表盘、执行任务、审批权限、审核变更、查看文件、终端和会话证据。
- 视觉气质：安静、可靠、精确、温暖；高信息密度，但不做传统后台式卡片堆叠。
- 主色：单一橘黄色，用于主操作、选中态和需要用户注意的状态。
- 输出尺寸：`1586 × 992`。
- 原型画布只包含应用内容区，不绘制原生窗口最小化、最大化和关闭按钮。

## 2. 产品术语

| 术语 | UI 含义 | 示例 |
| --- | --- | --- |
| 项目 | 用户可以独立进入、拥有仪表盘的代码项目 | `r-code`、`api-server` |
| 工作区 | 项目所附加的本地文件夹、访问权限和项目记忆配置 | `D:\project\rust\r-code` |
| 任务 | 用户交给代理完成的一项目标 | 修复任务队列并发问题 |
| 会话 | 围绕任务产生的对话和执行记录 | 任务的历史会话 |
| 主代理 | 对任务负责的代理 | `lin` |
| 子代理 | 主代理并行派出的执行单元 | 分析代理、测试代理 |
| 待处理 | 需要用户决定的权限、审核或失败事项 | `5` 项 |

规则：

- 左侧导航区统一写“项目”，不再把 `r-code` 和 `api-server` 称为工作区。
- “工作区”只出现在项目设置中，用于本地路径、访问模式和项目记忆。
- “任务”与“会话”不得混用；任务是目标，会话是记录。

## 3. 固定应用外壳

### 3.1 布局尺寸

| 区域 | 固定尺寸 |
| --- | --- |
| 顶部全局栏 | 高 `64px` |
| 左侧导航栏 | 宽 `312px` |
| 底部状态栏 | 高 `28px` |
| 右侧上下文面板 | 展开宽 `414px`，收起宽 `64px` |
| 主内容页边距 | `24px` |
| 主内容区块间距 | `24px` |

所有页面必须保留顶部全局栏、左侧导航栏和底部状态栏。右侧上下文面板按页面状态收起或展开，两个宽度和样式固定；项目仪表盘在没有选中对象时默认收起。

### 3.2 顶部全局栏

从左到右固定为：

1. R-Code 描边 Logo 与文字。
2. 项目选择器：全局页面显示“全部项目”，项目页面显示当前项目。
3. 全局搜索：“搜索任务、文件、对话…”，快捷键 `⌘K`。
4. 历史、通知、帮助、设置。
5. 主题快速切换。
6. 用户头像。

约束：

- Logo 只使用一种：橘色描边方形 `R` 标记，禁止实心方块版和纯文字版。
- 设置只保留顶部齿轮入口，左侧底部不再重复设置按钮。
- 顶栏控件高度统一为 `36px`。
- 主题快速切换固定放在“帮助”和“设置”之间；顶栏只在浅色与深色之间快速切换，完整的“跟随系统 / 浅色 / 深色”归属“设置 → 外观”。

### 3.3 左侧导航栏

固定顺序：

1. 新对话
2. 对话
3. 待处理
4. 活动
5. 文件夹
6. 项目树

“新对话”组件固定为：

- 宽 `284px`，高 `40px`。
- 左侧加号、文字“新对话”、右侧独立下拉区域。
- 使用纯色橘色，不使用渐变。
- 所有页面结构、图标和尺寸完全一致。

导航项固定为：

- 高 `40px`。
- 图标 `18px`，统一使用细描边图标，线宽约 `1.5px`。
- 激活态使用浅橘背景、深橘图标和正文；不使用左侧彩色粗线。
- 全局待处理数量统一显示 `5`。

项目树固定为：

- 项目名、状态点、活动任务数。
- 子项只显示任务名和状态点。
- 不在部分页面额外显示时间、文件图标或另一套任务卡片。

### 3.4 底部状态栏

所有页面固定显示：

`2 个项目 · 6 个会话运行中 · 数据实时`

任务页面可以在右侧追加当前分支或任务状态，但不得更换整套状态栏结构。

### 4.2 字体

- 中文与 UI 正文：`Noto Sans SC` / `Source Han Sans CN`。
- 代码与终端：`Cascadia Code` / `JetBrains Mono`。
- 不使用衬线展示字体；“新对话”首页也使用同一无衬线字体。
- 页面标题：`24px / 600`。
- 新任务起点 Hero 标题：`28px / 600`；仅用于无页面标题栏的单一开始状态。
- 区块标题：`16px / 600`。
- 正文：`14px / 400`，中文行高 `1.65`。
- 元数据：`12px / 400`。
- 数字列使用等宽数字。

### 4.3 间距与形状

- 基础布局使用 `4px` 网格，区块间距优先使用 `4 / 8 / 12 / 16 / 24 / 32px`。
- 结构宽度可使用 `20 / 28px`；控件内边距允许 `2px` 光学修正，例如 `10 / 14 / 18 / 22px`，不得随页面任意漂移。
- 控件圆角：`6px`。
- 全局“新对话”分裂按钮作为唯一高频主入口使用 `8px` 圆角；所有页面必须复用该例外，不能自行变体。
- 卡片圆角：`8px`。
- 大面板圆角：`10px`。
- 默认区域不使用阴影，只使用边框。
- 只有浮层、搜索面板和模态框使用阴影：`0 8px 24px rgba(61, 38, 20, 0.08)`。

## 5. 组件契约

### 5.1 按钮

- 主按钮：高 `36px`，纯橘背景，白字。
- 次按钮：白色背景、暖灰边框、深色文字。
- 危险按钮：默认白底红字，确认后才使用红色实底。
- 同一组操作只允许一个主按钮。
- 权限操作统一按“拒绝”“始终允许此工具”“允许一次”排列；“拒绝”为白底红字，“允许一次”为唯一橘色主按钮。

### 5.2 卡片与列表

- 卡片必须承载一个完整交互对象，例如权限请求、审核任务或项目。
- 普通数据行使用表格或分隔线，不额外套卡片。
- 禁止为每个标题添加装饰图标。
- 列表悬停使用 `surface-muted`；导航选中使用 `orange-100`，数据行和工作台对象的轻选中使用 `orange-050`。

### 5.3 状态标签

- 风险级别：`R1 / R2 / R3`，使用浅色小标签。
- 任务状态：运行中、待审核、已完成、已中断。
- 状态标签高 `22px`，圆角 `6px`，不使用全圆胶囊。

### 5.4 右侧上下文面板

- 面板顶部固定为标题、辅助操作和收起按钮；收起不等于清空当前对象。
- 内容随选择对象变化：审核摘要、权限详情、文件活动、验证与决策、事件证据。
- 底部操作固定吸附，仅在确实需要决定时出现。
- 收起态固定宽 `64px`，只显示展开按钮、当前面板名、状态点与数量，不在窄轨内塞入详情卡片。
- 窄轨必须保留展开前的语义：“审核摘要”收起后仍叫“审核摘要”，再展开恢复原内容和原操作。
- “项目动态”只在项目作用域内出现；新对话、对话列表和应用设置不渲染右栏。全局活动和待处理只在有明确选中对象时显示上下文面板。
- 项目仪表盘没有选中对象时默认收起；选择任务、审核项或文件后展开为 `414px`。
- 项目路径、权限模式、默认模型和项目记忆等稳定信息只出现在标题命令条，不在检查器重复展示。
- 检查器内部使用标题、留白和水平分隔线组织内容，不使用嵌套卡片。
- 任务对话默认不为“任务动态”预留右栏；只有用户点击某个子代理后，才打开对应的子代理检查器。关闭后恢复完整主对话宽度，不留下无语义窄轨。

### 5.5 任务运行与子代理渐进披露

任务概览中的运行反馈固定为三级信息深度：

1. 默认摘要：一条当前动作、一枚运行呼吸点、步骤数量和展开箭头。
2. 活动列表：点击摘要后显示经过整理的人类可读步骤；连续读取与搜索可合并，不展示内部事件名。
3. 技术详情：点击单一步骤后才显示 Shell、命令、输出、耗时和退出状态。

子代理使用同样的渐进关系：

1. 默认只显示“1 个子代理正在工作”及当前目标。
2. 展开后显示代理列表、状态与耗时。
3. 点击代理后打开右侧检查器，展示代理任务、活动与可公开结果。

约束：

- `tool_call`、`subagent_lifecycle`、`delegate_task`、`collect_subagents` 和原始 JSON 参数不得直接出现在普通产品界面。
- 私有推理始终不展示；检查器只呈现操作、进度、可公开结果和必要诊断。
- 运行中的呼吸效果只用于当前摘要与当前步骤，使用 `opacity + transform`，周期约 `1.8s`；必须支持 `prefers-reduced-motion`。
- 活动行默认无卡片外框，Hover 仅使用 `surface-muted`；单项技术详情可以使用一层细边框容器。
- 同一信息不得同时以完整列表、底部卡片和右侧检查器三份重复出现。

## 6. 页面布局规则

### 6.1 全局页面

适用：新对话、对话列表、跨项目活动、待处理、应用设置。

- 使用完整应用外壳。
- 项目选择器显示“全部项目”或当前作用域。
- 新对话、对话列表和应用设置不显示右栏；活动与待处理可显示当前选中对象的上下文面板。

### 6.2 项目页面

适用：项目仪表盘、项目文件、项目记忆。

- 顶部项目选择器显示当前项目。
- 左侧项目树保持不变。
- 项目仪表盘是点击项目后的默认落点。

### 6.3 任务页面

任务页面不得替换应用外壳。在主工作区内增加：

1. `56px` 高任务标题栏。
2. `44px` 高局部标签栏。
3. 固定标签：概览、变更、文件、终端、审核、回放。

“变更”“终端”“审核”“回放”只切换主工作区，顶部全局栏和左侧导航不发生变化。

“概览”默认是单列任务对话，不并排常驻执行计划或子代理卡片。运行活动与子代理以 5.5 的渐进披露组件嵌入对话；选择子代理后才出现右侧检查器。

### 6.4 文件页面

- 当前 `07-files-editor.png` 定义为“项目文件编辑器”，从左侧“文件夹”进入。
- 任务内“文件”是另一种页面状态，保留任务标题栏和局部标签栏，后续单独补图。

### 6.5 关键状态

`12-critical-states.png` 是状态规范板，不是产品路由。

后续拆分为：

- 首次启动：连接模型服务。
- 新对话：纯聊天、未附加文件夹。
- 活动页：恢复中断会话。
- 待处理：空状态。

## 7. 固定演示数据

所有页面必须以同一套 `prototype-fixtures.json` 为唯一数据基准。静态原型允许在构建时内联数据，但验收必须逐项对齐；不得在不同页面重新编造任务名、状态、行数或验证时间。

本页面集用于展示流程中的不同分镜，不表示同一时刻：00、02、04、05 是 `cargo test` 授权前，08、09 是授权并执行后的验证结果。真实产品实现必须使用同一后端状态源，不得复制静态分镜状态。

关键固定值：

- 全局：待处理 `5`、运行中 `4`、子代理 `6`、近一小时完成 `12`。
- `r-code`：待处理 `2`、运行中 `3`、子代理 `4`（跨任务去重活跃数）、近一小时完成 `8`。
- 项目树活动任务数：`r-code 4`、`api-server 2`，包含运行中、待审核或等待决定的活动任务，不等同于“运行中”列。
- 默认模型显示为“GPT-5”，不显示第三方 Logo。
- `修复任务队列并发问题`：
  - `src/queue.rs +24 -8`
  - `src/worker.rs +17 -3`
  - `tests/queue_test.rs +13 -2`
  - 总计 `+54 -13`
  - 授权后验证：`cargo test · 32 passed, 0 failed, 0 ignored · 148 ms`
- `统一错误处理规范`：
  - `src/error.rs +36 -8`
  - `src/api.rs +22 -6`
  - `tests/error_test.rs +18 -6`
  - `docs/errors.md +10 -4`
  - 总计 `+86 -24`
- `cargo test` 验证耗时固定为 `148 ms`。

## 9. 确定性原型源

- `prototype-src/index.html` 是统一入口，页面仅通过 `screen` 查询参数切换。
- `styles.css` 与 `core.js` 定义唯一应用外壳、令牌和共享组件；页面模块不得复制这些基础样式。
- `render-screens.cjs` 在浏览器中导出固定尺寸 PNG，并检查栏宽、字体、溢出以及禁用视觉效果。
- `verify-renders.cjs` 检查图片集合、尺寸与共享外壳的像素一致性。
- 后续修改必须先落到原型源，再重新导出 PNG；不直接修饰位图。
