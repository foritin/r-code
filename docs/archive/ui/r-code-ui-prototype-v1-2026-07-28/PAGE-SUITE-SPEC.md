# R-Code UI Prototype V1 — Page Suite Rewrite

状态：`00-master-project-dashboard.png` 已锁定为唯一视觉母版，01–12 核心页面与 13–16 任务运行交互状态已由同一套 HTML/CSS 组件确定性重绘。本文件定义各页面的职责、选中状态与内容结构。

## 1. 全套共同约束

- 画布固定为 `1586 × 992`，不绘制 Windows/macOS 原生窗口控制。
- 完整复用 00 母版的顶栏、左栏、底栏、描边 R Logo、纯色橘色“新对话”分裂按钮、字体、图标、线条、圆角和色彩。
- 全局页面的项目选择器显示“全部项目”；项目与任务页面显示“r-code”。
- 左栏顺序固定为：新对话、对话、待处理、活动、文件夹、项目树；待处理角标固定为 `5`。
- 底栏固定为：`2 个项目 · 6 个会话运行中 · 数据实时`。
- 主色固定为 `#E95B0B`；禁止渐变、玻璃拟态、装饰性阴影和无意义插画。
- 每组操作最多一个橘色主按钮。普通数据使用平面列表、表格和分隔线；不使用卡片套卡片。
- 右侧检查器有三种布局状态：不存在、收起 `64px`、展开 `414px`。收起只变化布局，不改变当前对象。
- “项目动态”仅属于项目作用域；新对话、对话列表与应用设置不显示右栏。审核、权限、文件或回放对象收起后，窄轨必须保留原面板名称并可恢复原内容。
- 检查器是连续暖灰平面，内部只使用标题、留白与水平分隔线，不放嵌套卡片。
- 所有可见任务、计数、差异统计、代理、风险等级和验证耗时必须以 `prototype-fixtures.json` 为唯一基准。静态原型可在构建时内联；不显示 Claude 或其他第三方 Logo，模型统一写 `GPT-5`。
- 页面集是流程分镜而非同一时刻快照：00、02、04、05 展示命令授权前，08、09 展示授权后验证完成；真实实现必须由后端单一状态源驱动。
- 中文界面使用无衬线字体；代码和终端使用等宽字体。文字必须清楚、拼写正确，避免生成不可读的小字。

## 3. 页面细则

### 01 新对话

- 复用完整外壳，项目选择器为“全部项目”，左栏“对话”激活。
- 主标题建议“开始一个新任务”，副文案说明可先纯聊天，稍后再附加项目。
- 中央仅保留一个大输入区，不叠多层卡片；输入区上方或底部展示 `未附加项目`、`风险模式`、`GPT-5`。
- 主操作为纯橘色发送分裂按钮；不得出现 OpenAI/Claude Logo、衬线大标题或独立左栏搜索框。
- 没有选中对象，不渲染右侧检查器，主区使用全部可用宽度。

### 02 跨项目活动

- 统计带固定为：待处理 `5`、运行中 `4`、子代理 `6`、近 1 小时完成 `12`。
- “需要你处理”使用两行平面动作列表：`运行 cargo test` 权限与 `统一错误处理规范` 审核，不做两张大卡片。
- 运行任务表使用固定 4 行：修复任务队列并发问题、实现分页查询接口、优化 Rust 编译性能、添加请求限流中间件。
- 最近完成使用固定 2 行：修复配置加载错误、更新依赖并修复告警。
- 默认选中 `统一错误处理规范`，右侧展开“审核摘要”，展示 `+86 -24`、4 个固定文件和 `cargo test · 已通过 · 148 ms`。
- 点击收起后窄轨仍显示“审核摘要”；再展开恢复同一摘要、文件、验证记录和底部操作，不得切换为“项目动态”。
- 底部操作只保留一个橘色主按钮“接受变更”，次操作“请求修改”“回滚”。

### 04 任务变更

- 任务标题固定为 `修复任务队列并发问题`，状态“运行中”，主代理 `lin`，风险 `R2`，时长 `00:18:42`。
- 在全局外壳内增加 56px 任务标题栏与 44px 标签栏：概览、变更、文件、终端、审核、回放；“变更”激活。
- 主区以平面双栏工作台组织：左侧任务活动/执行计划，右侧文件列表与代码差异。
- 固定变更：`src/queue.rs +24 -8`、`src/worker.rs +17 -3`、`tests/queue_test.rs +13 -2`。
- 当前活动显示“运行 cargo test”，可显示 2 个子代理；权限操作统一为“拒绝 / 始终允许此工具 / 允许一次”；不编造提交哈希。

### 05 待处理中心

- 项目选择器为“全部项目”，左栏“待处理”激活，页面总数固定为 `5`。
- 主列表采用分组平面行：明确展示 `运行 cargo test` 权限与 `统一错误处理规范` 审核；其余三项用类型汇总行表达，不编造新任务名。
- 默认选中权限请求，右侧展开“权限详情”：任务 `修复任务队列并发问题`、项目 `r-code`、命令 `cargo test`、请求者“测试子代理”、风险 `R2`。
- 收起后窄轨保留“权限详情”，再展开恢复同一命令请求。
- 底部操作固定为“拒绝”“始终允许此工具”“允许一次”，仅“允许一次”为橘色主按钮。

### 06 审核与验证

- 任务固定为 `统一错误处理规范`，状态“待审核”，主代理 `lin`；任务标签栏中“审核”激活。
- 文件列表与统计必须为：`src/error.rs +36 -8`、`src/api.rs +22 -6`、`tests/error_test.rs +18 -6`、`docs/errors.md +10 -4`，合计 `+86 -24`。
- 中部显示一个清楚的代码差异视图；右侧或下部用平面验证表显示 `cargo fmt 84 ms`、`cargo test 148 ms`、`cargo clippy 312 ms`，全部“已通过”。
- 吸底操作为“请求修改”“回滚”“接受变更”，仅“接受变更”为橘色主按钮。

### 07 项目文件编辑器

- 项目选择器为 `r-code`，左栏“文件夹”激活；这是项目文件页，不显示任务标签栏。
- 主区为连续三栏工作台：文件树、编辑器、展开的“文件活动”检查器。使用竖向分隔线，不给每栏再套卡片。
- 选中文件 `src/queue.rs`；编辑器展示可读 Rust 代码，代码区允许真实语法高亮，但不做发光效果。
- 检查器展示该文件与任务 `修复任务队列并发问题` 的关系，以及固定统计 `+24 -8` 和当前活动“运行 cargo test”。
- 顶部可保留“新建任务”“在终端打开”“保存”；同一操作组只有一个主操作，避免悬浮搜索面板遮挡代码。

### 08 集成终端

- 任务固定为 `修复任务队列并发问题`；任务标签栏中“终端”激活。
- 主区由终端会话列表与单一终端画布组成，使用分隔线而非卡片。
- 当前终端显示命令 `cargo test`、结果 `32 passed, 0 failed, 0 ignored`、状态“已通过”与耗时 `148 ms`。
- 深色终端仅用于真实输出区；其余应用外壳保持暖白。不得出现 neon、glow 或装饰性网格。
- 无额外对象选中时检查器收起 64px。
- 收起窄轨命名为“任务动态”，不使用“项目动态”混淆层级。

### 09 会话回放与分支

- 任务固定为 `修复任务队列并发问题`；任务标签栏中“回放”激活。
- 可保留“速览 / 探索 / 验证”作为主区内的次级模式，不替代任务标签栏。
- 主区使用平面回放章节列表与时间线；默认选中“修改 `src/queue.rs`”事件。
- 右侧展开证据检查器，显示 `src/queue.rs +24 -8`、后续 `cargo test · 已通过 · 148 ms` 及清楚的因果关系。
- 分支操作可以出现，但不得编造哈希或分支 ID；仅一个橘色主操作。

### 10 工作区与项目记忆

- 页面标题为“工作区与项目记忆”，项目选择器为 `r-code`。
- 将稳定信息集中在标题命令条：`D:\project\rust\r-code`、`风险模式`、`GPT-5`、`12 条记忆`。
- 主区使用“访问模式”分段控件与“项目记忆”编辑区，两者以标题和分隔线组织，不使用多层卡片。
- 项目记忆内容只使用与现有实现一致的规则示例；显示 `12 条规则`，不编造最近时间。
- 右侧检查器收起；不要再做“最近会话”“最近验证”信息卡堆叠。
- 收起窄轨名称为“项目动态”，因为本页仍处于 `r-code` 项目作用域。
- 主操作为“保存记忆”，次操作“放弃修改”。

### 11 模型服务与外部 CLI

- 使用统一外壳，项目选择器显示“全部项目”，顶部齿轮为唯一设置入口；左栏底部不重复设置按钮。
- 这是应用级设置，不显示“项目动态”或其他右栏。
- 设置内导航为平面窄栏；“模型服务”激活。服务列表、配置表单、CLI 诊断为连续三栏，不套大卡片。
- 模型显示为 `GPT-5`；接口地址使用中性占位内容，访问密钥必须掩码显示。
- 保留线路协议、最大输出、随机性、凭据安全状态等表单项；避免凭空加入厂商 Logo。
- 外部 CLI 只显示“CLI 可用 / 已登录 / 协作 Skill 已安装”及诊断入口。
- 主操作为“保存并用于新对话”，次操作“保存”。

### 12 关键状态规范板

- 明确标注“状态规范板 · 非产品页面”，不伪装成可导航的应用页面。
- 四个并排或 2×2 状态样例：首次启动 / 未连接模型服务；纯聊天 / 未附加项目；活动 / 恢复中断会话；待处理 / 空状态。
- 每个样例使用同一套控件、边框、按钮与文案尺度，减少框中框；状态编号只作索引，不做装饰徽章。
- 待处理空状态不编造完成记录；恢复状态只使用固定任务 `修复任务队列并发问题` 与 `统一错误处理规范`。
- 若缩略应用外壳会导致文字不可读，改用组件级状态截面；依然遵守统一 Logo、新对话按钮和橘色主操作规则。

### 13–16 任务运行与子代理

- 13 是默认态：主对话只显示一行“正在运行”摘要、状态呼吸点与耗时，不预先展开步骤、命令或右侧检查器。
- 14 是活动展开态：点击摘要后显示由用户语言描述的步骤；每行可悬停、聚焦和点击，不直接显示 `tool_call`、`subagent_lifecycle`、`delegate_task`、`collect_subagents` 或 JSON。
- 15 是命令详情态：点击某个技术步骤，只在该行下方展开 Shell 命令、耗时与公开输出；其他步骤保持紧凑。
- 16 是子代理详情态：主对话先展开子代理列表，再由具体子代理行打开右侧详情检查器；检查器可关闭，关闭后不留下无语义窄轨。
- 子代理详情只展示名称、状态、已运行时间、公开活动与结果；绝不展示私有推理、思维链或内部生命周期事件。
- 运行摘要、活动列表、子代理列表和检查器不得重复堆叠同一段内容；每一级只增加一层必要信息。
- 动画仅用于运行状态的低幅度呼吸提示；系统启用“减少动态效果”时必须停用。

## 4. 生成与验收流程

1. 原图只作功能参考，00 母版与 `UI-SPEC.md` 共同作为视觉约束。
2. 页面只在 `prototype-src/` 中实现，共享外壳和令牌不得在页面模块内复制。
3. `render-screens.cjs` 先将 12 张核心页面与 4 张任务运行状态导出到 `prototype-src/rendered/`，不直接覆盖正式图片。
4. 检查尺寸、外壳、导航状态、数据、术语、按钮主次、容器层级、字体和溢出。
5. `verify-renders.cjs` 再检查图片集合、尺寸，以及品牌区、搜索、“新对话”和底栏的像素一致性。
6. 全部通过后才原位替换正式 PNG；03 继续由 00 母版定义，不复制第二份母版；13–16 作为同一任务页的交互分镜保留。
