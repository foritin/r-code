本清单基于 r-code/docs/ 全套重构规范文档生成，覆盖 agent-core 模块从空仓到可发布的完整开发路径。
开发前置依赖：agent-core 公共合同子模块须以固定 commit 放在 vendor/agent-core，提供版本化共享 DTO / IPC 合同（R-Code 与 Tiny Hermes 共同消费）。

🖥️ 跨平台测试策略（无 macOS 真机场景）
当前开发者仅有 Windows 物理机，无 macOS 物理机。CI（.github/workflows/ci.yml）的 test job 已在 macos / windows 双平台矩阵上运行 cargo test --workspace --all-features，因此 Rust 层（单元 + 集成）测试在 macOS 上由 CI 覆盖，无需 Mac 真机。各测试层的平台覆盖分工：
测试层macOS 覆盖Windows 覆盖说明
单元测试（cargo test）✅ CI macOS runner✅ CI + Win 真机双平台矩阵，每次 PR/push 跑
集成测试（IPC/状态机/路径边界）✅ CI macOS runner✅ CI + Win 真机Unix Socket 与 Named Pipe 各自在对应平台 CI 验证
凭据存储（keyring）⚠️ CI 基本可测✅ Win 真机macOS Keychain 逻辑可测，授权弹窗 UI 需真机
桌面 E2E（Tauri + Playwright）⚠️ 需新增 CI E2E job✅ Win 真机CI 跑 headless 覆盖交互逻辑；建议 macOS/windows runner 各加一个 E2E job
原生 GUI（Dock 图标 / 菜单栏 / 原生对话框）❌ 需真机或云 Mac✅ Win 真机CI 无法验证原生视觉行为
安装包（DMG 真安装 / 签名 / notarize）❌ 需真机或云 Mac✅ Win 真机CI 可构建 DMG 并校验签名；"真安装/启动/清理"需真机
结论：日常开发中 macOS 自动化测试（单元 + 集成 + 部分 E2E）可由 CI 完全覆盖，无需 Mac 真机。仅 macOS 原生 GUI 与真安装/notarize 这一小块需发布前用云 Mac 服务（GitHub macOS larger runner / MacStadium 等）或借机做一次性真机 smoke。Windows 全链路真机验收由 Win 物理机承担。

已决策：JSONL 是会话内容源（source of truth），SQLite 是产品状态源。
数据流：
• Agent 产生 SessionEvent -> 先写 JSONL（crash-safe）-> 再投影元数据到 SQLite
• JSONL 存：完整消息内容、工具输入/输出、Usage（用于 Replay）
• SQLite 存：Task 状态机、Run 生命周期、tool_calls 元数据（name/risk/status，不含完整内容）、permission_requests、file_changes/baselines/blobs
• 崩溃恢复：先读 JSONL recover()（恢复对话），再读 SQLite（恢复 Task 状态）
• UI 查询：任务列表/权限/审计从 SQLite；时间线/Replay 从 JSONL
• 格式统一：内部会话和外部 CLI（Claude/Codex）都是 JSONL，Replay 解析器只需一套
