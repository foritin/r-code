第 1 章：R-Code 是什么？

如果你第一次听说 R-Code，这一章会告诉你它是什么、解决什么问题、以及它和日常使用的编辑器有什么本质不同。读完本章，你就能用一句话向朋友解释 R-Code。

一句话定义

R-Code 是一个「本地优先、任务原生、可观察、可审查、可回滚」的桌面 Agentic IDE。

这句话很长，我们拆开来看——每一个形容词都不是修辞，而是对应一个真实的技术决策：

先建立直觉

想象你有一个「结对编程伙伴」：它坐在你的笔记本本地，能读你的代码、改你的代码、跑你的终端命令，但每一步操作都记录在案，你随时可以「时间旅行」回到任意历史状态。这就是 R-Code 想提供的体验。

关键词含义对比
本地优先AI Agent 跑在你自己的机器上，代码不出本机vs. 云端沙箱（Replit、Cursor 远程模式）
任务原生最小工作单元是「Task（任务）」，不是「文件」vs. 以文件/标签页为中心（VS Code）
可观察Agent 的每一步推理、工具调用、Diff 都可见vs. 黑盒 AI 补全
可审查修改前可人工审批，支持 Ask / Edit / Auto 三种模式vs. 全自动无审批
可回滚字节级快照，任意历史状态一键恢复vs. 仅靠 Git commit 回滚

产品名变更：Charter → R-Code

R-Code 最初的名字是 Charter。在重构过程中，团队决定用更简洁的「R-Code」作为产品名，同时保留 charter/r-code 作为 GitHub 仓库路径。

Charter（原名）
→
R-Code（现名）
→
charter/r-code（仓库路径）
阅读代码时注意

你会在代码中同时看到 charter 和 r-code 两种命名。charter 出现在仓库 URL、部分旧注释和文档链接中；r-code 出现在 crate 名（r-code-core、r-code-host 等）和产品代码中。两者指同一个产品。

核心能力链

R-Code 的能力可以分为两条链：传统 IDE 链路和 Agent 工程链路。前者让你「写代码」，后者让 Agent「帮你写代码」。

传统 IDE 链路

这是你熟悉的编辑器操作，R-Code 一个不少：

打开项目
→
浏览文件
→
编辑代码
→
搜索内容
→
终端操作
→
Git 提交

Agent 工程链路

这是 R-Code 区别于传统编辑器的关键——一个完整的「AI 帮你干活」闭环：

① 创建任务
→
② 探索代码
→
③ 权限审批
→
④ 执行修改
→
⑤ 验证结果
→
⑥ 查看 Diff
→
⑦ 接受 / 回滚
关键洞察

传统 IDE 链路是「人驱动工具」，Agent 工程链路是「人驱动 Agent，Agent 驱动工具」。R-Code 把这两条链无缝融合在同一个界面里——你可以在同一个窗口里手动改两行代码，然后让 Agent 去重构一个模块。

一个具体的例子

假设你刚加入团队，被要求给登录页面加一个「记住我」复选框：

  1. 你在 R-Code 里创建一个 Task，目标描述：「给登录页加记住我复选框」
  2. Agent 探索 项目结构，找到登录页组件和样式文件
  3. Agent 提出修改方案，权限引擎 判断这是「写入操作」，需要你审批
  4. 你点击「接受」，Agent 执行修改：改 TSX、改 CSS、补测试
  5. Agent 验证：跑 TypeScript 编译 + 相关测试
  6. 你查看 Diff，确认改得对
  7. 点击「接受」——代码入库；或点击「回滚」——回到修改前状态

与 VS Code / Cursor 的区别

R-Code 经常被拿来和 VS Code、Cursor 比较。它们都是「写代码的工具」，但设计哲学截然不同。

设计哲学对比

维度VS CodeCursorR-Code
核心抽象文件 + 标签页文件 + AI 侧边栏任务（Task）
AI 角色补全 + Chat 插件补全 + 编辑指令结对编程伙伴
AI 运行位置云端云端（可选本地）本地进程
状态管理Git commitGit commit字节级快照 + 时间线
回滚粒度commit 级commit 级任意历史点
权限模型无有限四级风险分级
可观察性无部分完整推理链

「任务原生」vs「文件原生」

这是最根本的区别。VS Code 和 Cursor 的界面中心是「文件」——你打开一个文件，编辑，保存。R-Code 的界面中心是「任务」——你创建一个目标，Agent 围绕这个目标工作。

┌─────────────────────────────────────────────────────────┐ │ 文件原生（VS Code / Cursor） │ │ │ │ [文件 A] [文件 B] [文件 C] ... │ │ ↓ 人打开、人编辑、人保存 │ │ 上下文分散在多个标签页中 │ └─────────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────────┐ │ 任务原生（R-Code） │ │ │ │ Task: "给登录页加记住我复选框" │ │ ↓ Agent 围绕目标工作 │ │ [相关文件自动聚合] [推理过程可见] [Diff 可审查] │ └─────────────────────────────────────────────────────────┘

Agent 是本地进程，不是云端沙箱

Cursor 的 Agent 模式把代码发送到云端沙箱执行；R-Code 的 Agent 是一个运行在你本地的操作系统进程。这意味着：

  • 代码不出本机——满足企业合规要求
  • 可以访问本地环境——你的 SSH key、数据库、私有 npm registry
  • 延迟更低——不需要网络往返
  • 可离线工作——LLM 调用需要网络，但 Agent 运行时本身不依赖云端

可回滚到字节级

传统 IDE 依赖 Git commit 作为回滚点。R-Code 在 Git 之上增加了一层「字节级快照」：

  • 每次 Agent 修改前，自动创建快照
  • 快照存储在本地 SQLite 中，几乎零成本
  • 你可以「时间旅行」到任意历史状态，即使没有 Git commit
  • 支持「部分回滚」——只回滚某个文件，保留其他修改

为什么用 Rust

R-Code 用 Rust 从零重构。这不是「追新潮」，而是经过可行性分析后的理性选择（详见 docs/00-rust-rebuild-feasibility.html）。

考量Rust 的优势对 R-Code 的意义
性能 零成本抽象，接近 C 的速度 Agent 循环需要流式处理大量 token，UI 不能卡顿
内存安全 编译期保证，无 GC 暂停 长时间运行的 Agent 进程不会内存泄漏
跨平台 一次编写，Mac/Win/Linux 原生编译 R-Code 支持三大桌面平台
Tauri 配合 Tauri v2 原生 Rust 后端 前端用 React，后端用 Rust，共享类型
并发模型 async/await + Tokio 三进程架构需要大量异步 IPC
生态 serde、tokio、rusqlite、git2 核心依赖都有高质量 Rust 库
类比：Rust 之于 R-Code

如果说 TypeScript 是「带安全带的跑车」，Rust 就是「带防弹装甲的跑车」——你牺牲了一点开发速度，换来了运行时几乎不可能出现内存错误或数据竞争的保证。对于一个需要 7×24 小时运行的 Agent 进程来说，这个交换非常划算。

技术栈概览

R-Code 的技术栈可以概括为「Rust 后端 + Web 前端 + SQLite 存储」。

前端层 · React + TypeScript + Monaco Editor + xterm.js
应用框架 · Tauri v2（Rust + 系统 WebView）
后端核心 · Rust + Tokio（async 运行时）
存储层 · SQLite（rusqlite）+ JSONL（会话日志）
系统能力 · portable-pty（终端）· git2（Git）· notify（文件监听）

当前版本

R-Code 产品版本为 v1.0.0-beta.3 unsigned prerelease（Rust crate workspace 版本为 0.1.0）。

版本说明
  • v1.0.0 表示主版本 1，面向外部发布
  • beta.3 表示第三个公测版本
  • unsigned 表示尚未进行代码签名（macOS Gatekeeper / Windows SmartScreen 会提示）
  • prerelease 表示非正式生产版本

工作区内的 crate 版本遵循独立节奏：所有内部 crate 当前为 0.1.0，通过 [workspace.package] 统一版本号。

R-Code 的重构被拆分为 M1–M13 共 13 个里程碑，每个里程碑有明确的交付物和验收标准。

里程碑名称核心内容状态

M3IPC 通道JSON-RPC 2.0 进程通信已完成
M4Agent 运行时Agent loop、Runtime trait已完成
M5Tool Gateway工具注册、权限引擎、审计已完成
M6持久化层SQLite schema、事务、blob store已完成
M7终端系统PTY、Shell 集成、块模型已完成
M8渲染层React UI、Monaco、状态管理进行中
M9安全模型密钥链、路径校验、供应链进行中
M10外部 CLI 集成检测、replay、控制门待开始
M11UI/UX 打磨设计系统、组件规范待开始
M12测试与性能单元/集成/E2E/性能基准待开始
M13发布与运维签名、分发、恢复、签核待开始
里程碑不是瀑布

虽然编号从 M1 到 M13，但实际开发中多个里程碑可以并行推进。例如 M8（渲染层）和 M9（安全模型）的部分工作可以同时进行。里程碑更多是「依赖拓扑」而非「时间顺序」。

本章总结

现在，你应该能回答「R-Code 是什么」了。让我们回顾一下关键概念：

关键概念回顾

  • R-Code = 本地优先、任务原生、可观察、可审查、可回滚的桌面 Agentic IDE
  • 原名 Charter，仓库路径 charter/r-code
  • 两条能力链：传统 IDE 链路（人驱动工具）+ Agent 工程链路（人驱动 Agent，Agent 驱动工具）
  • 与 VS Code / Cursor 的核心区别：任务原生 vs 文件原生、本地进程 vs 云端沙箱、字节级回滚 vs commit 级回滚
  • 技术栈：Rust + Tauri + React + TypeScript + SQLite + portable-pty
  • 当前版本：v1.0.0-beta.3 unsigned prerelease
  • 里程碑：M1–M13，当前推进到 M8–M9

你应该能回答的问题

Q: R-Code 解决什么问题？

R-Code 解决的是「AI 编程工具缺乏可控性和可观察性」的问题。传统 AI 编辑器要么是黑盒补全（你不知道 AI 为什么这样改），要么是云端沙箱（你的代码要上传到别人服务器）。R-Code 把 AI Agent 放回本地，用「任务」组织工作，每一步都可审查、可回滚。

Q: R-Code 和 Cursor 有什么本质不同？

最本质的不同是「任务原生」vs「文件原生」。Cursor 是在编辑器里加了一个 AI 侧边栏，你还是在操作文件；R-Code 是以「任务」为中心，你给 Agent 一个目标，Agent 自己决定要改哪些文件。其次是 Agent 运行位置：Cursor 用云端沙箱，R-Code 用本地进程。

Q: 为什么不用 Electron 而用 Tauri？

Tauri 和 Electron 都能做桌面应用，但 Tauri 用系统自带的 WebView（不用打包 Chromium），后端用 Rust（不用 Node.js）。结果是：安装包更小（约 10MB vs 150MB+）、内存占用更低、启动更快。Rust 后端还带来了内存安全和性能优势。
