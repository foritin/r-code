第 12 章：渲染层

渲染层是 R-Code 的"脸面"——用户看到和交互的一切都在这里。本章介绍 Tauri WebView 中 React 应用的技术实现。

12.1 渲染层定位

渲染层运行在 Tauri WebView 中，是一个标准的 React 单页应用。它负责展示所有 UI、处理用户输入、与 Main 进程通信。

类比：网站与服务器

渲染层就像浏览器中运行的网站，Main 进程就像后端服务器。网站不能直接操作文件系统，必须通过 API 调用请求服务器代劳。

12.2 技术栈

层技术用途
桌面壳Tauri (Rust)跨平台窗口 + 系统 API
前端框架React + TypeScript + Vite组件化 UI 构建
编辑器Monaco Editor代码编辑 + Diff 视图
终端xterm.js终端模拟 + PTY 交互
状态管理Zustand轻量级全局状态
Schema 验证Zod运行时类型校验

12.3 进程隔离原则

渲染层遵循严格的安全隔离原则：

无 Node 集成
Renderer 无法直接访问 Node.js API
Context Isolation
Preload 脚本运行在独立上下文，与 Renderer 隔离
Sandboxing
Renderer 进程被操作系统级沙箱限制
安全意义

即使 Renderer 被恶意代码注入，攻击者也无法直接访问文件系统、环境变量或执行系统命令。所有特权操作都必须通过 Preload 桥，而 Preload 桥会进行 schema 验证。

12.4 Preload 桥

Preload 桥是 Renderer 与 Main 进程之间的唯一通信通道：

Renderer 进程 → window.__TAURI__.invoke() → Preload 脚本（schema 验证） → Main 进程处理

Preload 桥的关键特性：

  • 版本化：API 有明确的版本号，升级时保持向后兼容
  • Schema 验证：所有输入/输出通过 Zod schema 校验
  • 固定 channel：使用预定义的 channel 名称，不接受动态调用

12.5 Monaco Editor + xterm.js

R-Code 集成两大核心编辑器组件：

Monaco Editor（代码编辑）

  • VS Code 的核心编辑器组件
  • 支持语法高亮、自动补全、多光标、Diff 视图
  • 通过 Monaco Language Client 连接 LSP 服务器
  • 文件浏览 + 搜索 + 编辑一体化

xterm.js（终端模拟）

  • Web 端的终端模拟器
  • 通过 node-pty 或等价方案连接真实 shell
  • 支持 alternate-screen 程序（vim、htop 等）
  • 支持 OSC 133 序列标记提示边界

12.6 核心 UI 组件与布局

R-Code 的界面分为几个核心区域：

区域组件功能
侧边栏Workspace Explorer文件树、搜索、Git 状态
主编辑区Monaco Editor代码编辑、Diff 视图
底部面板xterm.js Terminal终端会话、任务输出
右侧面板Session Review审查 Diff、接受/回滚
顶部Toolbar运行验证、模式切换、设置

12.7 IPC 调用模式

从 Renderer 发起的一次工具调用，经过以下路径：

Renderer (React 组件)
    │
    ▼ window.__TAuri__.invoke('tool_call', payload)
    │
    Main 进程 (Tauri/Rust)
    │
    ▼ ToolGateway 风险分类 + 路径边界检查
    │
    Worker 进程 (Agent Runtime)
    │
    ▼ 执行工具调用
    │
    结果 → 脱敏 → 审计记录 → 返回 Renderer
为什么经过 Worker 进程

Agent 逻辑运行在独立的 Worker 进程中，避免阻塞 Main 进程的 UI 响应。Worker 完成工具调用后通过 IPC 返回结果。

12.8 状态管理

渲染层使用 Zustand 进行轻量级全局状态管理：

  • UI 状态：侧边栏展开/折叠、当前活动面板、主题选择
  • 会话状态：当前 Task、AgentRun 列表、审查状态
  • 编辑状态：打开的文件、未保存的修改、光标位置
  • 持久状态：通过 IPC 从 SQLite 读取，不在 Renderer 本地持久化

12.9 会话编排 UI

R-Code 支持多会话编排，通过以下 UI 概念实现：

概念说明
Rail（轨道）一个会话的时间线，显示从创建到审查的完整过程
Formation Wall（编队墙）多会话并排对比视图，用于监控多个 Agent 任务
Director Slot（导播位）当前用户正在审查/交互的主会话区域

12.10 Replay 回放系统

Replay 功能允许用户回放整个会话过程：

读取 JSONL 事件流 → 按时间顺序重放 → 逐步还原 UI 状态 → 用户可暂停/跳转

回放系统基于 JSONL 事件日志实现，因此可以精确还原任意时刻的会话状态。

12.11 主题系统

R-Code 支持多种视觉主题：

主题模式说明
暗色（Dark）默认深色背景，适合长时间编码
亮色（Light）可选浅色背景，适合明亮环境
皮肤变体 1-4扩展不同的强调色组合

主题系统支持 prefers-color-scheme 自动跟随系统设置。

12.12 CSP 与 iframe 沙箱

渲染层的安全策略包括：

策略说明
CSP（Content Security Policy）限制脚本来源，禁止内联脚本执行
iframe sandbox预览帧只能连接本地回环开发服务器
导航限制Renderer 不能跳转到外部 URL
window.open 限制新窗口需要显式用户授权
权限请求摄像头/麦克风等需要用户授权
不暴露 Pi

Renderer 层绝不直接 import Pi SDK 类型。所有 Pi 相关的逻辑封装在 Worker 进程内部。这是硬性架构约束。

开发者工具

R-Code 的开发者工具不暴露 Pi 内部状态。调试信息经过脱敏处理，不会泄露 Provider 密钥或敏感配置。
