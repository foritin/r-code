第 11 章：打包与发布

本章介绍 R-Code 的打包流程、三平台产物、签名策略以及从 Beta 到 Stable 的晋升路径。

11.1 发布流程总览

R-Code 的发布流程如下：

代码合并到 main → CI 全部通过 → 创建 SemVer Tag → 打包三平台产物 → 生成 SBOM + 校验和 → GitHub Release 发布
类比：软件发货

把发布想象成网购发货：CI 是质检，Tag 是订单号，打包是装盒，SBOM 是装箱单，GitHub Release 是快递单号。每一步都留有记录，出了问题可以追溯。

11.2 SemVer 版本策略

R-Code 遵循 Semantic Versioning 规范：

版本格式示例含义
MAJOR.MINOR.PATCH1.0.0正式稳定版
MAJOR.MINOR.PATCH-beta.N1.0.0-beta.3公开预览版（prerelease）
  • Beta：1.0.0-beta.N — 功能完整但未经广泛验证，unsigned 发布
  • Stable：1.0.0 — 需要完成签名、公证、SmartScreen 兼容
release-policy 守护

scripts/release-policy.mjs 会在 unsigned 模式下拒绝 stable SemVer（如 1.0.0）。这确保 unsigned 二进制不会被误标为正式版本。

11.3 当前状态：unsigned prerelease

当前 R-Code 处于 unsigned prerelease 模式：

# 默认环境变量
CHARTER_SIGNING_MODE=unsigned
平台签名状态用户影响
macOSAd-hoc 签名（无 Developer ID）Gatekeeper 显示"无法验证开发者"
Windows无 Authenticode 签名SmartScreen 警告
Linux无额外签名层需手动配置 chrome-sandbox

11.4 macOS 打包

macOS 使用 Tauri CLI (tauri-cli) 打包为 DMG 安装镜像：

当前：Hardened Runtime

# 打包命令
CHARTER_SIGNING_MODE=unsigned npm run package -- --mac

Tauri 自动启用 Hardened Runtime 和 entitlements，但不进行 Developer ID 签名或 Apple 公证。

未来：签名 + 公证

Stable 发布需要完成以下步骤：

  1. 获取 Apple Developer Program 会员资格
  2. 生成 Developer ID Application 证书并导出为 .p12
  3. 配置 App Store Connect API 凭证
  4. 通过 Tauri 的公证流程提交 (未来)
  5. 使用 stapler 装订公证凭证

验证命令

codesign --verify --deep --strict --verbose=2 Charter.app
codesign -dvvv Charter.app
spctl --assess --type execute --verbose=4 Charter.app
xcrun stapler validate Charter.app

11.5 Windows 打包

Windows 使用 NSIS 生成安装程序（.exe）：

当前：无签名

CHARTER_SIGNING_MODE=unsigned npm run package -- --win

未来：Authenticode 签名

需要获取公开信任的 Authenticode 证书，然后通过 CI 签名：

WIN_CSC_LINK -> Tauri 的证书链接
WIN_CSC_KEY_PASSWORD -> 证书密码

验证方法：

signtool verify /pa /all /v Charter.exe
SmartScreen 兼容性

新颁发的 Authenticode 证书需要建立"声誉"（reputation）后 SmartScreen 才会信任。首次发布仍可能看到警告，这是正常现象。

11.6 Linux 打包

Linux 发布为 tarball 压缩包，包含 setuid sandbox：

# 打包
npm run package -- --linux

# 安装后配置 sandbox
sudo chown root:root <extracted-dir>/chrome-sandbox
sudo chmod 4755 <extracted-dir>/chrome-sandbox

# 启动
<extracted-dir>/charter
禁止 --no-sandbox

不要使用 --no-sandbox 启动 Linux 版本。setuid sandbox 是保证 Renderer 进程安全的关键防线。

Beta 升级说明

当前 Beta 版本不支持自动升级。用户需要手动下载新版本、备份应用数据目录、验证新制品后替换。

11.10 秘密管理（CI secrets）

签名和公证相关的敏感信息存储在 GitHub Environment Secrets 中：

Secret 名称用途平台
MAC_CSC_LINKBase64 .p12 证书macOS
MAC_CSC_KEY_PASSWORD证书密码macOS
APPLE_API_KEYApp Store Connect API KeymacOS
WIN_CSC_LINKWindows 签名证书Windows
WIN_CSC_KEY_PASSWORD证书密码Windows
安全规则

签名密钥仅限受保护的 tag Job 使用，不得暴露给 PR 或 fork。一旦怀疑泄露，立即轮换并吊销旧证书。

11.11 Stable 发布阻塞项

从 Beta 晋升到 Stable 必须完成以下条件（当前均未勾选）：

  • ☐ 获取 Apple Developer Program 会员资格和 Developer ID 证书
  • ☐ 配置 Apple 公证凭证并通过 Gatekeeper 验证
  • ☐ 获取受信任的 Windows Authenticode 证书
  • ☐ 在干净 SmartScreen 机器上验证安装/卸载
  • ☐ 运行 Beta-to-Stable 升级/回滚测试
  • ☐ 完成 20 项真实 Provider 评估
  • ☐ 产品负责人签字确认 Stable 测试报告
