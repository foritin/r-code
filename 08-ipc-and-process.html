IPC 与进程通信

1. 概述

Charter 的进程间通信连接 Main、Agent Worker 和 Renderer。
Rust 重构使用 Unix Socket（macOS/Linux）和 Named Pipe（Windows）
替代 Electron 的 MessagePort。

2. 通信拓扑

│  Main (Tauri Rust)                          │
│  ┌─────────────────────────────────────┐   │
│  │  IPC Server                          │   │
│  │  - Unix Socket / Named Pipe          │   │

3. 协议设计

3.1 JSON-RPC 2.0

jsonc
// 请求
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "method": "task.create",
  "params": { "goal": "Fix the bug" }
}

// 响应
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "result": { "taskId": "task-123" }
}

// 事件（无 id）
{
  "jsonrpc": "2.0",
  "method": "agent.event",
  "params": { "taskId": "task-123", "event": {...} }
}

3.2 消息类型

  • 请求：需要响应的调用。
  • 响应：请求的结果。
  • 事件：单向推送，无需响应。

4. 通道划分

4.1 Main ↔ Agent Worker

  • 任务创建/恢复/中止。
  • 工具调用/结果。
  • 事件流。

4.2 Main ↔ Renderer

  • 状态同步。
  • UI 事件。
  • 投影数据。

4.3 外部 CLI ↔ Main

  • 终端控制门（Unix Socket）。
  • HTTP 协议。

5. Schema 校验

5.1 请求校验

  • 所有请求必须符合 JSON Schema。
  • 无效请求返回 ParseError。

5.2 响应校验

  • 成功响应包含 result。
  • 错误响应包含 error。

11. Rust 实现要点

rust
// IPC Server
struct IpcServer {
    listener: UnixListener,
    handlers: HashMap<String, Box<dyn IpcHandler>>,
}

#[async_trait]
trait IpcHandler {
    async fn handle(&self, params: Value, ctx: &IpcContext) -> Result<Value, IpcError>;
}

// IPC Client
struct IpcClient {
    stream: UnixStream,
    pending: HashMap<String, oneshot::Sender<IpcResponse>>,
}

impl IpcClient {
    async fn call(&mut self, method: &str, params: Value) -> Result<Value, IpcError> {
        let request = IpcRequest::new(method, params);
        self.send(&request).await?;
        // wait for response with matching id
    }
    
    async fn send(&mut self, request: &IpcRequest) -> Result<(), IpcError> {
        let json = serde_json::to_vec(request)?;
        let len = json.len() as u32;
        self.stream.write_all(&len.to_be_bytes()).await?;
        self.stream.write_all(&json).await?;
        Ok(())
    }
}
