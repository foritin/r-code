产品范围、端到端流程与验收合同

1. 重构目标不是“把 Electron 翻译成 Rust”

Charter 的重构目标是交付一个 local-first 的 Agentic IDE：用户可以在一个可恢复、可审查、
可回滚的工作单元中，让内置 Agent、Claude Code 与 Codex 在真实仓库工作，并且始终看见
权限、终端、文件、证据与最终决策。技术迁移（Electron/Node → Tauri/Rust）只是实现手段。

以下内容是产品合同。实现顺序、crate 名称或 UI 组件可改变，但任何重构版本都必须保留
这些可观察行为。

2. 顶层对象与不可变边界

对象用户可理解的含义必须持久化的最小字段不能被混淆为
Project / Workspace一个被允许访问的真实工作目录规范化根路径、显示名、信任状态、最近打开时间临时工作树
Task / Session一次可恢复的人机协作工作单元目标、项目、状态、时间线、审查结论单条聊天消息
Agent RunTask 内一次有生命周期的执行runtime、开始/结束、取消原因、恢复引用Task 本身
Tool CallAgent 提议或执行的最小受控动作参数摘要、风险、决定、结果、审计序号终端输出文本
Terminal用户或 Agent 可见的真实 PTY 表面cwd、所属 Project/Task、缓冲和控制状态任意 shell 子进程
Change / Evidence对“做了什么、是否可信”的可审查证据基线、diff、验证结果、截图/日志引用自动生成的最终总结
Review Decision用户对当前变更的决定接受范围、理由、时间、操作者Git commit

所有状态变化写入追加式事件；数据库中的“当前状态”只是投影。任何重启、恢复、导出或审查都
必须能从事件和关联的不可变证据解释当前界面。

3. 支持的关键用户旅程

3.1 首次启动与安全基线

  1. 应用建立用户数据目录、数据库与日志目录，失败时显示可操作的诊断，不静默清空数据。
  2. 用户选择或添加工作区；应用规范化路径、检查目录存在性与工作树状态。
  3. 用户配置 Agent / 外部 CLI / 模型和隐私选项；秘密只由主进程或系统 keychain 接触。
  4. 未配置模型时仍可浏览项目、终端和历史，但不能伪装成 Agent 已可执行。

验收：冷启动、坏数据库、只读用户数据目录、缺失模型配置四种情况均有明确状态与安全退出路径。

3.2 创建并执行一个任务

  1. 用户在已选 Project 中输入目标、选择 agent、自治度、模型与验证计划。
  2. 创建 Task、记录工作基线，必要时创建隔离 worktree；任何失败都不能污染原工作区。
  3. Agent 先探索/规划，再在策略允许的情况下执行工具；实时事件投影到对话、活动、文件和终端。
  4. 每个高风险动作进入同一份待决权限记录，任何 UI 入口的决定必须影响同一调用。
  5. Agent 结束后进入验证与审查，绝不把“文本说完成”直接映射为已接受。

验收：中途关闭、权限拒绝、工具错误、Agent 崩溃、验证失败均能回到可继续/可审查/可回滚的状态。

3.3 观察、介入与审查

  • 用户可在不停止 Agent 的情况下查看活动、文件热度、差异、命令输出与当前行动。
  • 用户可追加目标、附加代码/文件/截图/预览元素，并清楚看见附件进入了哪个 Task。
  • 用户可批准、拒绝或要求修改；批准范围可以是整体、文件或 hunk，接受不等于自动提交。
  • 回滚前必须显示将恢复的基线与外部变更冲突，绝不静默覆盖用户刚刚保存的内容。

3.4 外部 CLI 与多 Agent 编排

Charter 需要把 Claude Code / Codex 既作为可观察外部会话，也作为受控的终端 worker。外部 CLI
控制必须经过同一权限、令牌、暂停与账本边界；不能因为调用来源是“另一个 Agent”而绕过策略。
具体协议见 03-terminal-system、05-session-orchestration、10-external-cli-integration。

5. 硬性不变量

  1. 一个 Task 任意时刻最多一个活跃 Agent Run；并行 worker 是该 Run 的受控子实体。
  2. 未完成高风险 Tool Call 不能进入 REVIEW_READY 或 ACCEPTED。
  3. ACCEPTED 是用户接受当前变更，不等于 commit、push 或发布。
  4. 任务基线在第一次可写动作前建立；回滚只能恢复可证明归属的字节。
  5. 外部会话的原始记录保持只读，解析失败不能改写其来源文件。
  6. 所有外部 URL、文件路径、IPC payload 和 tool 参数都在信任边界重新校验。
  7. 取消、重启和 worker 退出都必须留下可区分的终止原因；不得显示成正常完成。

6. 发布级 Definition of Done

一个功能在“看起来能用”之外，必须同时满足：

  • 有用户可见的空态、加载态、失败态和恢复入口。
  • 有 domain 层单元测试、主进程/IPC 集成测试和桌面 E2E 证据；渲染变化须在目标与窄视口检查。
  • 有权限、数据归属与隐私评审；涉及写入时有回滚或清晰的不可逆提示。
  • 有可观测日志、错误 code 与支持包字段；日志不能携带秘密或完整敏感内容。
  • 有文档链接到对应的设计、合同、测试与发布条件。
